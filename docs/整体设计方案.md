# 零食发明机 · 价格预测器 — 整体设计方案

> 主题词：零食 ｜ 功能词：预测器 ｜ 风格：涂鸦手绘
> 版本：v1.0 ｜ 日期：2026-10-24 ｜ 状态：待用户评审

---

## 一、项目概述

**一句话定位**：一台涂鸦手绘风的「零食发明机」——用户亲手拼装（或摇杆随机、或涂鸦签名）创造一款世上不存在的零食，机器煞有介事地预测它的价格，吐出一张超市小票风格的「价格预测报告单」。

**核心气质（灵魂）**：半真半假流。
- **真实的一半**：成本结构锚定现实，再折算成自创货币「咔滋币 KZ」（薯片基底 320 KZ、芝士粉 180 KZ）。
- **整活的一半**：溢价明细负责搞笑——「情绪价值费 180 KZ」「罪恶感附加税」「黑暗料理风险金 520 KZ」。

**目标体验**：像小时候在课本上画「我要发明的零食」。一轮 60~120 秒的轻互动，结果可截图分享到群里当梗图。

**机器名**：零食发明机 SNACK-O-MATIC 3000（副标题：v0.3 内测版，永远内测版）

---

## 二、核心玩法流程

```
① 拼装台（主干）：选基底 → 选配料(≤4) → 选酱料(≤2) → 选包装
② 命运摇杆（加分）：一键随机 roll 出黑暗料理组合
③ 涂鸦签名（加分）：小画布上画两笔 → 升级为「艺术家联名款」
④ 预测仪式：按下大红按钮 → 机器运转动画（指针狂摆/读条/蒸汽）
⑤ 输出：小票弹出 —— 成品涂鸦图 + 逐项价格明细 + 总价 + 鉴定评语 + 手绘条形码
```

三条路径都通向同一个预测引擎，摇杆和画布是拼装的快捷方式与增值项。

**Demo 范围**：只做「选基底/配料/酱料/包装 → 预测 → 生成小票」主流程；M2 命运摇杆、M3 涂鸦画布暂不开发、不在界面展示。依赖摇杆的隐藏款发掘机制与依赖画布的艺术家联名费同步后置，物料数据与完整产品方案保留。

## 三、功能模块拆解

| 模块 | 职责 | 要点 |
|---|---|---|
| M1 拼装台 | 分类选项卡 + 已选托盘 + 实时预览 | 单选/多选规则、上限拦截提示 |
| M2 命运摇杆（后续） | 随机生成一套组合 | Demo 不做；强制制造「甜咸冲突」保证黑暗料理感 |
| M3 涂鸦画布（后续） | Canvas 画板：3 色笔 + 橡皮 + 清空 | Demo 不做；笔迹合成进报告单，作为「设计签名」 |
| M4 预测引擎 | 估价算法 + 溢价触发规则 + 评语库 | 纯前端、同组合结果稳定（种子随机） |
| M5 仪式动画 | 按下按钮后的机器运转演出 | 1.5~3 秒，可跳过，营造期待感 |
| M6 报告单 | 小票渲染 + 截图引导 | 撕票动画 + 「啪」的鉴定章 |
| M7 数据中心 | 配料库 / 价格表 / 溢价规则 / 文案库 | 独立数据结构，与 UI 解耦 |

### 4.3 货币与计价公式

**自创货币：咔滋币（KZ）**
- 原 `10~20 倍` 只作为放大气质的参考；为满足三位数价格带，各款按相对贵贱重新校准，不做机械汇率换算。
- **所有物料单价与溢价标价均 ≥100 KZ，且都是 10 的倍数**，例如 `200 / 320 / 470 KZ`，个位固定为 `0`。
- 最终预测价 **不足 500 KZ 时按 500 KZ 保底**；常见组合预计落在 `2000~6000 KZ`。
- 金额格式示例：`3,290 KZ`，中文可读作「三千二百九十咔滋币」；界面与小票只展示咔滋币，不出现人民币。

```text
① 物料小计 S = 基底 + Σ配料 + Σ酱料 + 包装
② 溢价小计 P = Σ命中的溢价项（见 4.4，可叠加）
③ 预测服务费 F = 200 KZ（含机器磨损与拍脑袋工时）
④ 玄学浮动 R = (S + P) × 种子随机数[-5%, +8%]，四舍五入到十位
⑤ 未取整总价 = S + P + F + R
⑥ 最终总价 T = max(500, ceil(未取整总价 ÷ 10) × 10)
```

Demo 的种子由「全部选项 id」生成：同一组合反复预测结果一致，换任意配料才重新定价；后续接入涂鸦画布后再把签名状态加入种子。小票仍逐项展示 `S / P / F / R / 取整保底`，让一本正经的计算过程本身成为笑点。

### 4.5 鉴定评语库（按总价 × 怪异度双维度）

**价格维度（咔滋币）**
- `<1500 KZ`：「便宜得让人不安，建议直接量产」
- `1500~2990 KZ`：「定价合理，隔壁小卖部已连夜研究你」
- `3000~4990 KZ`：「有点飘了，但消费者可能为情怀买单」
- `5000~7990 KZ`：「这不是零食，这是轻奢单品」
- `≥8000 KZ`：「建议申遗，或报警」

**怪异度维度**
- 0~2：「稳中带皮，老少咸宜」
- 3~5：「口味大胆，胆小勿试」
- 6+：「发明它的人应该被写进教科书（反面案例）」

## 七、插画资源清单（AI 生成，共 52 张）

**物料插画（48 张）**：基底 10 + 常规配料 18 + 酱料 8 + 包装 6 + 隐藏款 6，每款独立一张，与物料库 id 一一对应。

**装饰插画（4 张）**：机器本体 1、大红按钮 1、涂鸦贴纸 2（星星箭头组 / 蒸汽爆炸组）。

**生成与验收节奏**：分 4 批（基底+包装 → 常规配料 → 酱料+隐藏款 → 装饰），每批生成后逐张验收，风格跑偏或主体不清的重 roll；全部使用统一 prompt 模板，仅替换主体描述。

**Prompt 统一模板（保证风格一致）**：
```
{主体描述}, doodle hand-drawn style, crayon and marker sketch,
rough wobbly lines, childlike drawing on white paper,
single object, centered, no text
```
生成接口：`text_to_image?prompt={...}&image_size=square`（选项用 square，机器本体用 portrait_4_3）

**落地方式**：生成后下载至 `assets/img/`，本地引用（保证离线可用），文件按 `base-*.png / topping-*.png / sauce-*.png / pack-*.png` 命名。

## 八、技术方案

| 项 | 方案 |
|---|---|
| 形态 | 单个自包含 `index.html` + `assets/` 文件夹，零 JS 依赖 |
| 字体 | Google Fonts 在线加载 + 本地降级栈（`font-display: swap`） |
| 涂鸦画布 | 原生 Canvas API（笔迹导出为 dataURL 合成进报告单） |
| 预测引擎 | 纯前端 JS；`mulberry32` 种子随机 → 同组合结果可复现 |
| 手绘边框 | 内联 SVG path + `vector-effect: non-scaling-stroke`，避免图片拉伸失真 |
| 报告单分享 | 优先引导「截图/长按保存」，不引入 html2canvas 等重型库 |
| 响应式 | ≥900px 双栏；<900px 单列（拼装台在下、预览+按钮置顶吸底） |
| 目录结构 | `snack-predictor/ ├── index.html ├── assets/img/ └── docs/整体设计方案.md` |

## 十、风险与备忘

- **插画风格一致性**：全部走统一 prompt 模板 + 同批生成，验收时逐张过，不合格重roll。
- **中文字体加载慢**：`font-display: swap` + 系统手写体降级，文字永不消失。
- **截图分享依赖用户操作**：小票做成「长按即存」友好的独立视觉块。
- **价格免责**：报告单底部固定一行小字「*本预测由 SNACK-O-MATIC 3000 拍脑袋认证，如有雷同，纯属它抄你」。
